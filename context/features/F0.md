# F0 — Platform
## Goal
Provide the foundation every feature relies on: repo, CI, auth/roles, job queue, audit log, immutable versioning.
## Depends on
Nothing.
## Inputs / Outputs
`/auth/login`, `/jobs/{id}`, `/jobs/{id}/cancel`, `/audit`; internal services `audit.record()`, `versioning.create_version()`, `jobs.enqueue()`.
## Business rules
- A `dataset_version` is immutable once written (file checksum stored and verifiable).
- Every state change writes an `audit_event`.
- Roles: Analyst, Approver, Admin; default deny.
- Jobs survive a restart and report progress 0-100 and support cancel.
## Build items
Monorepo scaffold per ARCHITECTURE.md; Docker Compose (Postgres, Redis, sample source DB with seed data); CI (lint, type-check, unit, integration); migrations for DATA_MODEL.md; JWT auth; RBAC dependency; Parquet read/write helpers; job runner; audit service.
## Out of scope
Any feature logic (F1-F8), UI beyond login and a job-status component.
## Acceptance criteria
1. `docker compose up` starts Postgres, Redis, API, worker and sample source DB.
2. CI runs lint, type-check and tests on every push and fails on error.
3. Login returns a token; endpoints reject missing/wrong role with 401/403.
4. `versioning.create_version()` writes a Parquet file + checksum; attempting to overwrite fails.
5. `audit.record()` is called on every write path (test enumerates write endpoints).
6. A job enqueued, then worker killed and restarted, still completes.
7. A running job can be cancelled and reports `cancelled`.
## Tests required
Unit (auth, checksum), integration (restart survival, RBAC matrix), immutability test.

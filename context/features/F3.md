# F3 — Profile data
## Goal
Automatically describe every column so users understand the data at a glance.
## Depends on
F1, F2.
## Inputs / Outputs
`POST /versions/{id}/profile` (job), `GET /versions/{id}/profile`, `/jobs/{id}`.
## User flow
Select dataset -> Start profiling job (background, progress shown) -> Save results -> Display profile.
**Shows:** types, nulls, distinct counts, min/max/mean/percentiles, distributions, semantic detection (email, phone, date, ID, currency).
## Business rules
- Results cached per `dataset_version_id` (hit on same version, miss on new).
- Semantic detection returns a type plus confidence; threshold configurable.
- Job is cancellable and shows progress.
## Out of scope
Quality scoring, issue detection (F4).
## Acceptance criteria
1. Numeric stats equal an independent pandas/DuckDB computation (tolerance 1e-9).
2. Null %, distinct counts exact.
3. Histogram bins for numeric/date; top-N values for categorical.
4. Semantic detection on `golden_clean`: precision >= 95% and recall >= 90% for email, phone, date, ID, currency columns.
5. Re-running on the same version returns cached result instantly; new version recomputes.
6. Cancelling a job stops it and leaves no partial profile.
7. 1M rows profiled in < 3 minutes (D13).
## Tests required
Unit (stat functions), integration (job lifecycle), golden (semantic detection), edge (mixed types, empty, wide), performance.

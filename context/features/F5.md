# F5 — Investigate
## Goal
Show the evidence behind each issue so the user trusts it before changing anything.
## Depends on
F4.
## Inputs / Outputs
`GET /issues/{id}`, `GET /issues/{id}/records`, `PATCH /issues/{id}/status`, `GET /issues/{id}/export`.
## User flow
Open an issue -> See affected records with flagged cells -> Read "why flagged" -> Mark as valid / ignore, or export rows.
## Business rules
- Read-only on data. Marking valid/ignored changes issue status only and recalculates the score.
- "Why flagged" text is specific (rule, value, threshold), not generic.
## Out of scope
Fixing data (F6).
## Acceptance criteria
1. Affected-row count shown equals the issue's `affected_count`.
2. Flagged cells are highlighted at the correct row/column (checked vs answer key).
3. Marking an issue valid removes it from the open board and the score recalculates.
4. Export CSV contains exactly the rows shown, including row index.
5. Status changes write audit events.
## Tests required
Integration (counts, score recalculation), golden (cell positions), UI (flagged cell highlight, empty/error states).

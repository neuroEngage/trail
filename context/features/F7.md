# F7 — Compare
## Goal
Prove the impact of cleaning by comparing two versions on the numbers the business uses.
## Depends on
F6.
## Inputs / Outputs
`POST /comparisons` (job), `GET /comparisons/{id}`.
## User flow
Pick two versions or snapshots -> Choose metrics or a saved SQL query -> Run -> Side-by-side values, deltas, distribution overlay.
## Business rules
- Metrics: row count, null %, distinct, mean, sum, median, min/max per column, plus score per dimension.
- Saved SQL runs per D11: single statement, SELECT only, read-only connection, 30 s timeout, 100k row limit. The query is executed against each version.
## Out of scope
Writing data, scheduled comparisons.
## Acceptance criteria
1. Deltas equal hand-computed values on a small fixture.
2. SQL sandbox rejects DROP, UPDATE, INSERT, ATTACH, COPY, multi-statement and comment-smuggled statements.
3. Timeout and row limit enforced with readable errors.
4. Distribution overlay data present for numeric columns.
5. Comparing a version with itself gives zero deltas.
## Tests required
Unit (delta maths), security (SQL injection list), integration, UI.

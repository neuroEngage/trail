# F4 — Quality assessment
## Goal
Find data problems and produce an explainable score per dimension plus a ranked issues board.
## Depends on
F3.
## Inputs / Outputs
`POST /versions/{id}/assessment` (job), `GET /versions/{id}/assessment`, `GET|POST /datasets/{id}/rules`.
## User flow
Run assessment -> Built-in checks (duplicates, missing and disguised nulls, invalid formats, outliers, inconsistent categories) -> Custom rules (e.g. end date after start date) -> Score per dimension -> Issues board ranked by severity.
## Business rules
- Dimensions: completeness, validity, uniqueness, consistency, accuracy (D9), timeliness (D10).
- Score formula per D12; every point deducted links to an issue.
- Disguised nulls list is configurable (`N/A`, `-`, `999`, `null`, `none`, empty string, `?`).
- Outliers via IQR (default) with configurable multiplier.
- Custom rule expressions are validated; syntax errors return 422 with a readable message.
- Every issue is clickable (id used by F5).
## Out of scope
Showing records (F5), fixing (F6).
## Acceptance criteria
1. On `golden_dirty.csv`: recall >= 95% and precision >= 90% per defect type vs the answer key.
2. `golden_clean.csv` overall score >= 98 and zero high-severity issues.
3. Scores are reproducible (same input => same output).
4. Sum of deductions equals 100 - dimension score (traceability test).
5. Custom rule `end_date >= signup_date` flags exactly the planted violations.
6. Invalid rule expression returns 422, not 500.
7. Issues board sorted by severity then affected_count.
## Tests required
Unit (each check), golden (answer key), property test (score within 0-100), integration (job), UI board.
